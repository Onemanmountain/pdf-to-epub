# pdf-to-epub

把扫描版 PDF 转成**可重排（reflowable）EPUB** 的本地流水线：视觉侦察 → MinerU 解析 → 结构重建 → 三级校验+整页仲裁 → pandoc 封装 → 自动质检。目标阅读器是 Kindle——成品以能顺利经亚马逊服务器转 KFX 为准绳。

> Scanned-PDF → reflowable EPUB pipeline. v0.3.0：视觉裁判（提案权只归看过页面的环节）× 结构调和器（唯一章节树权威）× 脚注规范化（Kindle 弹窗）。**规则零硬编码**：每本书的结构规律由系统在运行时发现、验证、生成、用完即弃。目前针对现代简体中文图书调优。

## 为什么需要它

Calibre 直接转 PDF 常常切错章、丢版式；纯 OCR 工具转出来的文字带着满身错字就封装了；MinerU 解析强大，但标题检测在美术字篇名页上会失灵、目录页条目会被误当标题。本项目的增量是**侦察层 + 结构层 + 校验层**：转换前先让视觉模型"翻一翻"这本书、现场总结出它的结构规律；转换后对 OCR 结果做三级漏斗审查，拿不准的一律保守保持原文并记入报告——宁可多审，绝不改错。

## 架构（v0.3.0）

```
PDF ─► Phase 0  Scout 侦察
        本地 VL 抽样看 16 页 → 确定性信号聚合出候选规则
        → 外部强模型仲裁（可插拔，可选）→ book_profile.json（本次运行的立法，用完即弃）
    ─► Phase 1  MinerU 解析（markdown + 插图 + 块坐标 middle_json）
    ─► Phase 2  结构重建 + 结构调和（四方证据 → 唯一章节树 → 现存标题逐个审判：
        边界佐证且落位正确=# / 编号章题=## / 仅字体投票=###（不入大纲）/ 目录区条目=正文）
    ─► Phase 3  三级校验（启发式 → 视觉裁决：VL 裁块转录是唯一提案源；
        文本模型只能否决不能提案；收缩+唯一性护栏）
    ─► Phase 3+ 批量智能仲裁（整页 VL 重判 → 不定则外部强视觉终裁 ARK；
        双视觉一致才落地；终局保持原文附理由——是决策，不是转人工）
    ─► Phase 3.6 脚注规范化（按页配对 → 全书连续 [^n] → EPUB3 弹窗脚注）
    ─► Phase 4  pandoc 封装 → EPUB 自动质检（zip 结构 / manifest / TOC 落点对账）
    ─► conversion_report.json（全程审计；各阶段决策与理由留痕）
```

架构图见 `docs/architecture-v0.2.0.html`（浏览器打开；v0.3.0 版图待更新）。

## 实测效果（auto 模式，零人工干预；与 v0.2.0 同书对比）

### 《漫长的革命》（250 页，8 编 + 2 附录，编-章结构）

| 维度 | v0.2.0 | v0.3.0 |
|---|---|---|
| EPUB 大纲 | 66 条：目录页幻影标题 5 个、编名页残留半标题 3 个、正文加粗误当标题、封底文字混入 | **40 条纯净章节树**（12 编级 + 25 章 + 前置页），页序全部正确；幻影/残留/误标**在机制上消失**（调和器审判，非逐条补丁） |
| 文本修正 | 17 存疑 → 落地 3 处，事后查明**全部是整段截断破坏**（165 字被换成 66 字片段） | 同位置 10 存疑 → 落地 4 处**全部零截断**（修正文本均长于原文：238→292 等），双视觉一致才落地；保持 6 处均附理由 |
| 脚注 | 页脚注按页①重置，流式格式歧义 | **67 条全部转为全书连续编号的 EPUB3 弹窗脚注**（67 个引用 + 67 个 aside，Kindle 兼容），3 页保守跳过附理由 |
| 人工兜底 | needs_human=True（14 处丢给人类） | **needs_human 开关已废除**：升级链爬到外部强视觉终裁，终局决策附理由 |

### 《读书的方法与艺术》（200 页，23 篇选本）

| 维度 | v0.2.0 | v0.3.0 |
|---|---|---|
| EPUB 大纲 | 40 条：含 MinerU 字体投票噪声（篇内强调句混入大纲） | **26 条**（23 篇目 + 前置页）；14 处篇内强调**保留为三级标题**——正文里仍是粗体，大纲里不出现 |
| "鲁迅"案 | 文本裁判无视觉提案繁体"魯迅"，judge+VLM 双确认落地（事故） | 视觉裁决机制下**无从产生繁体提案**，原样保持简体——事故机制根除 |
| 存疑项 | 2 处保守保持 → needs_human | 3 处全部保持原文**附理由**，零转人工旗标 |

## 快速开始

前提：Windows + NVIDIA GPU（8GB+）、`pandoc` 在 PATH、MinerU venv（`~\mineru-venv` 或 `MINERU_VENV`）、Ollama 便携版（qwen3:8b + qwen2.5vl:7b）。

```powershell
# 交互式（推荐）：逐项询问，auto/guided 可选
.\scripts\pdf-to-epub.ps1

# 直接命令行
.\scripts\pdf-to-epub.ps1 -Pdf book.pdf -Title 书名 -Author 某人 -Mode auto

# GUI（最简图形界面，批量智能模式）
C:\Users\<你>\mineru-venv\Scripts\python.exe gui.py   # 然后开 http://127.0.0.1:7861

# 引擎裸 CLI
python -m engine.pipeline --pdf book.pdf --title 书名 --mode auto
```

双模式：`auto` 批量智能（零干预，不一致项保守保持原文并记报告）；`guided` 主动审阅（校验后暂停，人工改 md 后回车继续封装）。

## 配置

- `config.yaml`：入库模板（本地 ollama 为默认后端）
- `config.local.yaml：**gitignored**，放外部仲裁 API 凭证（OpenAI 兼容端点：`api_base` / `api_key` / `api_model`）。配上后 Phase 0 自动启用外部仲裁层；不配则纯本地运行（聚合层兜底）。
- 环境变量 `SCOUT_API_KEY` 可覆盖 key。

## 已知不足（诚实清单）

详见 `docs/limitations.md`。v0.3.0 经用户审阅发现的六处异常（全部已定根因、定方案，即 v0.3.1 内容）：

1. **重复文段**：裁块带 15% 背景边距，视觉模型把相邻段落的尾巴也抄进了修正文本，整段替换后邻段结尾重复出现（另有一起简体被擅转繁体）
2. **页眉混入正文**：书名页眉从未清理，多处黏进正文句子，甚至插断词语（"必""然"分跨两页，页眉夹中间）
3. **目录格式不一致**：目录印两页，MinerU 给出两种排版，照单全收
4. **换页处多余引号**：OCR 在换页处多识字符；暴露校验漏斗没有"成对符号配对"检测器
5. **视觉换行未重排**：纸面行尾软换行被保留（"我们把/握了"），电子书里显示为真实断行
6. **中文序数未识别**："其一"（文本型块）未像"其二/三"（标题型块）一样成为小标题——序数形态家族只认阿拉伯数字

另：外部强视觉终裁层已具备能力但两书实测中本地层全部裁定、未获实战触发；MinerU 解析时长书间差异较大（200 页约 5 分钟 / 250 页约 26 分钟）；本地 Scout 16 页约 27 分钟。

## 路线图（已立项，v0.3.1 内容，方案已经用户审阅批准）

- **裁块提示词修正**：明示"图中含目标文段及背景，只转录目标"；写回前对齐校验，剥除已知属于邻段的头尾内容
- **页眉剥离**：同字符串在 ≥3 页的页首/页尾重复即判为页眉，独立行删除、句中黏连剥除；从第一篇正文起算，保护封面版权页
- **目录区格式统一**：目录区条目统一为列表格式
- **成对符号检测**：引号/书名号/括号逐段配对检查，失衡入视觉漏斗裁决
- **中文重排**：段内视觉换行 CJK 并接；跨段碎段（前段无句末标点）合并，自动修复被页边界打断的词
- **序数形态家族**：「其 N / 第 N / N.」同族合法化——同形态 ≥2 个标题票即合法，整行同形态文本一律提升为小标题
