# 技术路线与设计决策

## 总览

```
PDF ──► MinerU(standard 档, GPU) ──► markdown + images/ + middle_json(块坐标)
        │
        ▼
   Stage A  规则启发式：全书块级扫描 → 十余个可疑点
        │
        ▼
   Stage A3 Qwen3-8B 文本裁判：逐条判 wrong/corrected（think 关闭）
        │
        ▼
   Stage B  Qwen2.5-VL 视觉复核：按 bbox 裁块 300dpi 渲染，VLM 只读小图
        │
        ▼
   Stage C  双确认一致 + 全文唯一 → 自动改；其余 → needs_review 人工审
        │
        ▼
   人工改 -fixed.md → pandoc → EPUB（图片相对路径，目录/元数据齐）
```

## 关键决策与理由

### 1. 解析用 MinerU standard 档而非 basic 档
basic 档错字率是数量级的差距（实测："梁启超"→"梁登起/梁否越"、"胡适"→"胡商"×2）。standard 档的 GPU 版式分析 + 更优 OCR 把可疑点压到个位数/十位数，校验层才有意义。**治本优先于治标的纠错。**

### 2. 校验不全盘检验，做漏斗
7-8 万字全书逐句喂 LLM 既慢又引入幻觉。改为三级漏斗：规则启发式把全书筛成十余个可疑点 → 文本裁判快速裁决 → VLM 只对可疑点定向复核。成本从"全书几遍"降到"十几张小图"。

### 3. VLM 禁整页，按 bbox 裁块
实测整页 300dpi 喂 4bit VLM：330 秒/页，不可用。裁块后几秒一张，且小图转录准确率显著更高。块坐标来自 middle_json（standard 档必出）。

### 4. 双确认铁律
裁判（文本模型）单独会幻觉——实测它两次把正确文本判错并给出乱码纠正（如"學運還遠還還"）。因此：**裁判与 VLM 的读数规范化（去空白/标点）后一致，且与原文不同，才允许自动修改**。两模型相互独立，同时以同样方式出错的概率远低于单模型。

### 5. 唯一性护栏
自动替换用字符串匹配定位。可疑文本若在全文出现多次（如短词人名"鲁迅"），`replace` 会命中第一处——可能改错位置。因此只有**全文唯一**的文本才自动改，多处出现一律转人工。

### 6. 双推理后端
- `ollama`（默认）：便携安装、模型即服务、脚本自动拉起 serve；`qwen3:8b`（裁判）+ `qwen2.5vl:7b`（视觉）
- `transformers`：直连 HF 权重 4bit 量化，不依赖服务，适合无 Ollama 环境
两后端对同一本书的关键判读实测一字不差（p158 书法"胡適書法"、p212"新文學運動……"）。两模型各约 6GB 显存，**串行加载、用完即卸**（ollama 用 `keep_alive=0`）。

### 7. 提示词工程的两个实测教训
- **Qwen3 裁判必须 `think=False`**（ollama 后端），否则思考链拖慢且 JSON 提取不稳
- **VLM 转录 prompt 必须字形中立**：写"繁体字按原样输出"会诱发系统性繁体输出（prompt 里出现"繁体"二字即偏置源）。现行 prompt："按图中实际字形原样输出，不要把简体转换成繁体，也不要把繁体转换成简体"

### 8. 环境隔离
Windows 上若存在用户级 `PYTHONPATH`（某些工具会设置），它会污染所有 Python 进程的 import 解析，把残缺环境伪装成可用。脚本调用外部 Python 前一律临时清空 `PYTHONPATH`；装机自检用：

```powershell
$env:PYTHONPATH=$null; python -m pip check
```

## 参考耗时（200-263 页书，RTX 级 GPU）

| 阶段 | 耗时 |
|---|---|
| MinerU 解析 | ~5-10 min（约 0.7 页/秒） |
| Stage A+A3 裁判（13 处） | ~10-15 min |
| Stage B VLM（2-6 处） | ~2-5 min |
| 人工审 | 看 needs_review 数量，通常 5 min |
| pandoc 封装 | 秒级 |
