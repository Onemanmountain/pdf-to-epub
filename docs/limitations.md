# 已知边界与失败案例

本页是诚实的负面清单。使用前请读完——知道工具不能做什么，和知道它能做什么同样重要。

## 1. "校验通过"不是"全书无误"

Stage A 的启发式只能抓**长得像错误**的文本：

| 模式 | 例子 |
|---|---|
| `digit_in_word` 数字嵌词 | "方法5技巧" |
| `isolated_short` 孤立短块 | 被拆块的人名/题字（1-2 字） |
| `heading_pagenum` 标题页码尾缀 | "梁启超 002" |
| `trad_mix` 繁简混杂 | 简体段落混入多个繁体字 |
| `rare_chars_in_heading` 标题生僻字 | OCR 把常见字错成生僻字 |

**完全不覆盖**：断句错误、通假/同音误字、语义级错误、图表内文字、页眉页脚混入正文。7.8 万字的书实际只抽查十余处，没有 ground truth 就谈不上召回率。

## 2. 竖排文字是公认盲区

实测案例：某书 p2 竖排两列题字"读书的方法与艺术 / 中国图书评论学会编"——

- OCR 输出：揉成一团（"中国图书评论学会\n第1章\n三册"）
- VLM 复核：幻觉（"中国图书馆学全书"）
- 另一本书 p28 竖排古文页：OCR 与 VLM 双双失败，只能原样保留

**结论**：竖排（题字/古籍/书法）一律靠人工审兜底，不要期待自动处理。

## 3. 低清书法字的裁块级 VLM 转录仍会出错

实测案例：简体"鲁迅"署名的低清裁块（楷体+扫描噪声），"鲁"字底笔糊成类似四点形状，VLM 与辅助视觉模型**双双**读成繁体"魯迅"；看整页高清渲染则能确认是简体。

**结论**：裁块级复核在小块/低清/书法字体上可信度下降。护栏（双确认+人工）是承重墙。改进方向（0.1.1 候选）：对超小 bbox 提高 dpi 与外扩边距重裁。

## 4. 裁判模型有幻觉，且输出有随机性

- 裁判曾把正确文本判错并给出合并下文式纠正（"胡适"→"读书 胡适"），甚至乱码纠正（"學運還遠還還"）
- 判官是采样生成（temperature 0.1），同一批可疑点两次运行的裁决可能略有出入

这些都是**预期内**行为——双确认铁律存在的理由。看到 needs_review 条目多时不要慌，那是护栏在工作。

## 5. 章节切分未经历复杂版式考验

两本测试书都是单栏、标题规整的简单版式，MinerU 切章漂亮。多栏混排、脚注穿插、章中插图的书，标题层级判断可能崩——而那一步错了后面全错，目前没有对应的校验环节。

## 6. 工程限制

- **单机单卡串行**：两模型各约 6GB 显存不能同时常驻，校验是"裁判跑完卸、VLM 上"的串行模式；批量转换未做并行化
- **人工审是吞吐瓶颈**：双确认把所有不确定转给人脑，批量场景下人是瓶颈
- **CPU 未测试**：全流程在 NVIDIA GPU 上验证；CPU 理论上可跑（慢），未验证
- **启发式字符集是手写小集合**：繁体字表/生僻字表只针对现代简体中文图书调优，其他语种需自行扩展
- `Invoke-Item` 自动打开 EPUB 是桌面行为，headless/服务器环境应去掉

## 7. 文本裁判看不见页面（机制级问题，v0.3.0 重构）

校验漏斗中"裁判"环节是纯文本模型：它拿不到页面图像，只能基于上下文猜。字符级报警尚有上下文可倚；**段落级报警时它输出的"修正建议"是残缺碎片**（实测：把"中国目前的人口在7.5亿到8亿之间"改成"中国目前的人口在7。"）。v0.2.0 的收缩护栏堵住了落地端，但根源未除：**修改提案权不该交给看不见证据的环节**。v0.3.0 将改为视觉裁判（提案只从证据产生），文本模型降为只能否决。

## 8. 标题体系没有调和层（机制级问题，v0.3.0 重构）

MinerU 的标题标签是**页面局部字体投票**（只看字号/粗体），不知道目录页的行是"条目"、编名页第二行是篇名的组成部分、正文加粗句只是强调。v0.2.0 的 Phase 2 只做加法（补漏掉的篇/编标题），不做调和——于是目录页条目、编名页残留块、正文加粗句仍以标题身份漏进成品（实测第二本书的大纲即因此出现重复/错位）。深层缺失：**没有"结构权威"概念**——各方证据（页眉规则、目录页条目、字体投票、编号模式）应降为输入，由调和器计算唯一章节树，标题全部由树重新生成。讽刺的是，书的目录页本身就是最权威的结构证据，目前完全未被利用。

## 9. 页脚注编号不适配流式格式（v0.3.0 已立项）

扫描书的脚注按页从①重置——纸书以页为单位没问题，流式 EPUB 里多个①互相歧义，且脚注块卡在页边界会拦腰截断段落。v0.3.0 方案：全书连续编号 + pandoc 原生 `[^n]` 脚注（EPUB3 标准 aside/noteref），按页归组配对，配对失败保守跳过；验收准绳为 Kindle（能顺利转 KFX）。

## 失败案例档案（供复现）

| 案例 | 现象 | 根因 | 处置 |
|---|---|---|---|
| 中间文件误选 | `'list' object has no attribute 'get'` | 按文件大小选 JSON，选到 pages 为 list 的 `model_output.json` | v0.1.0 已修：按文件名匹配 |
| VLM 繁体偏置 | 简体页面全读繁体 | prompt 里"繁体字按原样输出"诱发 | v0.1.0 已修：字形中立 prompt |
| ollama 冷启动误判失败 | `failed to start within 45s` | 本机冷启动 1-2 分钟 | v0.1.0 已修：150s + 早退检测 |
| 依赖缺失却"能跑" | 换台机器/换个 shell 就崩 | 用户级 PYTHONPATH 走私依赖 | 文档自检 + 脚本隔离 |
| 段落级纠正删内容 | 165字段落被换成66字片段 | 裁判无视觉输出截断碎片；长文本天然过唯一性检查 | v0.2.0 收缩护栏；v0.3.0 视觉裁判根治 |
| 编级标题静默缺失 | 大纲只有"目录/索引"两个边界 | 组合页眉全等匹配失败+回看窗口不足+落位行窗过小 | v0.2.0 已修（包含匹配/6页回看/单调游标） |
| 聚合层过拟合 | 纪实书"名人生平段"被判为篇界信号 | 确定性阈值无法区分文集引子段与正文叙事 | v0.2.0 外部仲裁层否决（设计内刹车生效） |
